# กติกาการบันทึก Changelog

โปรเจกต์นี้มีไฟล์ `CHANGELOG.md` ที่ root สำหรับบันทึกประวัติการเปลี่ยนแปลงทั้งหมด
แบบเรียงตามเวลาต่อเนื่อง

## เมื่อใดต้องอัปเดต

ทุกครั้งที่มีการเปลี่ยนแปลงโค้ดหรือโครงสร้างที่ผู้ใช้มองเห็นผล ให้เพิ่มบันทึกลง
`CHANGELOG.md` ก่อนจบงาน เช่น เพิ่ม/แก้ฟีเจอร์, แก้บั๊ก, refactor ที่กระทบพฤติกรรม,
เพิ่ม/ลบ/อัปเกรด dependency, เปลี่ยนการตั้งค่า build

ไม่ต้องบันทึกสำหรับ: การพิมพ์ผิดเล็กน้อยในคอมเมนต์, การจัดรูปแบบล้วน ๆ,
หรือการเปลี่ยนแปลงที่ไม่กระทบพฤติกรรมและไม่มีนัยสำคัญ

## บันทึกอย่างไร

1. **เพิ่มรายการใหม่ต่อท้ายไฟล์เสมอ (ล่าสุดอยู่ล่างสุด)** ห้ามแทรกกลางไฟล์
   - ถ้ามีหัวข้อ "Backlog" อยู่ท้ายสุด ให้แทรกรายการใหม่ไว้ **ก่อน** หัวข้อ Backlog
2. ใช้หัวข้อ `## N. <ชื่อสั้น ๆ>` โดยต่อเลขจากรายการสุดท้าย และระบุ commit hash
   สั้นในวงเล็บถ้ามี เช่น ``## 8. เพิ่ม unit tests (`abc1234`)``
3. จัดกลุ่มรายละเอียดด้วยหัวข้อย่อยมาตรฐาน:
   `Added`, `Changed`, `Fixed`, `Removed`, `Deprecated`, `Security`
4. เขียนสั้น กระชับ เป็นภาษาไทย โฟกัสที่ "อะไรเปลี่ยนและทำไม" ในมุมของผู้ใช้/นักพัฒนา
   ไม่ใช่รายละเอียดการแก้ทีละบรรทัด
5. ตรวจให้ครบทุกไฟล์ในชุดการเปลี่ยนแปลงก่อน commit เพื่อไม่ให้ตกหล่น

## ตัวอย่าง

```markdown
## 8. เพิ่มหน้าประวัติการสั่งอาหาร (`abc1234`)

**Added**

**Fixed**

```
