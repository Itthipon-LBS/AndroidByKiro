# กติกาการบันทึก Changelog

โปรเจกต์นี้มีไฟล์ `CHANGELOG.md` ที่ root สำหรับบันทึกประวัติการเปลี่ยนแปลงทั้งหมด

## เมื่อใดต้องอัปเดต

ทุกครั้งที่มีการเปลี่ยนแปลงโค้ดหรือโครงสร้างที่ผู้ใช้มองเห็นผล ให้เพิ่มบันทึกลง
`CHANGELOG.md` ก่อนจบงาน เช่น เพิ่ม/แก้ฟีเจอร์, แก้บั๊ก, refactor ที่กระทบพฤติกรรม,
เพิ่ม/ลบ/อัปเกรด dependency, เปลี่ยนการตั้งค่า build

ไม่ต้องบันทึกสำหรับ: การพิมพ์ผิดเล็กน้อยในคอมเมนต์, การจัดรูปแบบล้วน ๆ,
หรือการเปลี่ยนแปลงที่ไม่กระทบพฤติกรรมและไม่มีนัยสำคัญ

## บันทึกอย่างไร

1. เพิ่มรายการใหม่ไว้ใต้หัวข้อ `## [Unreleased]` เสมอ
2. จัดกลุ่มด้วยหัวข้อย่อยมาตรฐาน Keep a Changelog:
   `Added`, `Changed`, `Fixed`, `Removed`, `Deprecated`, `Security`
3. เขียนสั้น กระชับ เป็นภาษาไทย โฟกัสที่ "อะไรเปลี่ยนและทำไม" ในมุมของผู้ใช้/นักพัฒนา
   ไม่ใช่รายละเอียดการแก้ทีละบรรทัด
4. ถ้ามี commit จริง ให้ระบุ commit hash สั้นกำกับหัวข้อได้ (optional)
5. เมื่อจะออกเวอร์ชัน ให้ย้ายรายการจาก `[Unreleased]` ไปไว้ใต้หมายเลขเวอร์ชัน
   พร้อมวันที่ (รูปแบบ `YYYY-MM-DD`)

## ตัวอย่าง

```markdown
## [Unreleased]

### Added
- เพิ่มหน้าประวัติการสั่งอาหาร (OrderHistoryFragment)

### Fixed
- แก้ยอดรวมคำนวณผิดเมื่อจำนวนสินค้าเกิน 99
```
