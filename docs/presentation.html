เทสต์ควบคุม input (action) และตรวจ output (state/event) โดยแทนที่ data layer ด้วย fake

ทำไมโค้ดนี้เทสต์ง่าย

  • แยก layer ชัด — logic อยู่ใน ViewModel ไม่ปนกับ View
  • พึ่งพา interface (FoodRepository) ไม่ใช่ implementation จริง
  • ฉีด dependency ผ่าน constructor → สลับเป็น fake ได้ง่าย
  • state เป็น StateFlow อ่านค่าได้ตรง ๆ, event เป็น Flow ทดสอบด้วย Turbine

ขั้น 3: MainDispatcherRule

viewModelScope รันบน Dispatchers.Main ซึ่งไม่มีจริงในเทสต์ JVM จึงต้องสลับเป็น test dispatcher

class MainDispatcherRule(
    val testDispatcher: TestDispatcher = StandardTestDispatcher()
) : TestWatcher() {
    override fun starting(description: Description) {
        Dispatchers.setMain(testDispatcher)
    }
    override fun finished(description: Description) {
        Dispatchers.resetMain()
    }
}

ขั้น 3: FakeFoodRepository

ใช้ fake แทน mock — คืนเมนูคงที่ คาดเดาได้ ไม่ต้องพึ่ง data source จริง

class FakeFoodRepository(
    private val menu: List<MenuItem> = DEFAULT_MENU
) : FoodRepository {
    override suspend fun getMenu(): List<MenuItem> = menu

    companion object {
        val ITEM_A = MenuItem(1, "ผัดกะเพรา", "เผ็ดร้อน", BigDecimal("55"))
        val ITEM_B = MenuItem(2, "ข้าวมันไก่", "นุ่มลิ้น", BigDecimal("50"))
        val DEFAULT_MENU = listOf(ITEM_A, ITEM_B)
    }
}

ขั้น 4: โครงเทสต์แบบ AAA

flowchart LR
    A["Arrange
สร้าง ViewModel + fake"] --> B["Act
addToCart / placeOrder"] --> C["Assert
ตรวจ uiState / event"]
        
@Test
fun `addToCart increments quantity and totals`() =
    runTest(mainDispatcherRule.testDispatcher) {
        val viewModel = createViewModel()
        advanceUntilIdle()                       // Arrange

        viewModel.addToCart(ITEM_A)              // Act
        viewModel.addToCart(ITEM_A)

        val state = viewModel.uiState.value      // Assert
        assertEquals(2, state.cart.first().quantity)
        assertEquals(0, BigDecimal("110").compareTo(state.cartTotal))
    }

}

ขั้น 4: 12 เคสที่ครอบคลุม

  • โหลดเมนูเข้า uiState ตอน init • สถานะเริ่มต้นว่าง
  • addToCart เพิ่มจำนวน + อัปเดต count/total
  • ยอดรวมของสินค้าหลายชนิด
  • decreaseQuantity จนเหลือ 0 → รายการหาย
  • decreaseQuantity ตอนมากกว่า 1 → ยังอยู่
  • placeOrder ตะกร้าว่าง → ไม่ยิง event
  • placeOrder มีของ → ยิง OrderPlaced + เคลียร์ตะกร้า
  • restore จาก SavedStateHandle
  • round-trip: สร้าง ViewModel ใหม่แล้วตะกร้ายังอยู่
  • decreaseQuantity สินค้าที่ไม่มี → no-op
  • คงลำดับการเพิ่มสินค้า (insertion order)

Best practices ที่ใช้

  • 1 Fake แทน Mock (คุมง่าย เปราะน้อย)
  • 2 MainDispatcherRule คุม coroutine
  • 3 ทดสอบที่พฤติกรรม (black-box) ไม่ผูก implementation
  • 4 Turbine สำหรับ Flow / event
  • 5 BigDecimal เทียบด้วย compareTo (กันปัญหา scale)
  • 6 ตั้งชื่อเทสต์เป็นประโยค อ่านเข้าใจทันที
