Navigation ใน Android (ฉบับสมบูรณ์)

อธิบายการนำทาง (Navigation) ระหว่างหน้าจอบน Android ครบทุกส่วน — แนวคิด graph/host/controller, back stack, การส่งข้อมูล (Safe Args), single-activity, XML vs Compose Navigation, deep link, nested graph + bottom nav — พร้อมภาคปฏิบัติสร้างจริง, ข้อดี/ข้อเสีย, การเลือกใช้ และแนวโน้ม อ่านจบแล้วนำไปใช้ได้ทันที

สรุปสั้นสุด: ใช้ Navigation Component (Jetpack) จัดการย้ายหน้า + back stack แบบรวมศูนย์ • วางทุกหน้าจอไว้ใน nav graph เดียว มี NavHost เป็นที่ แสดง และ NavController เป็นตัวสั่งย้าย • ส่งข้อมูลด้วย Safe Args (type-safe) • นิยมทำแบบ single-activity

1. Navigation คืออะไร

Navigation คือการย้ายผู้ใช้ระหว่างหน้าจอในแอป และจัดการ "ประวัติการย้าย" (back stack) ให้กดปุ่ม back ย้อนกลับได้ถูกต้อง

เดิมทำเองด้วย FragmentManager.beginTransaction() หรือ startActivity() ซึ่งจัดการ back stack/ส่งข้อมูล/animation ยุ่งและพลาดง่าย — ปัจจุบันใช้ Navigation Component (Jetpack) ที่รวมทุกอย่างไว้ที่เดียว

Navigation Component จัดการให้: การย้ายหน้า, back stack, ส่งข้อมูลแบบ type-safe (Safe Args), transition/animation, deep link — แบบรวมศูนย์ในที่เดียว

2. แนวคิดหลัก 3 อย่าง

องค์ประกอบคือเปรียบเทียบ
Navigation Graphแผนที่รวมทุกหน้าจอ (destination) + เส้นทางเชื่อม (action)"แผนผังเส้นทาง"
NavHostที่ว่างในหน้าจอที่ใช้แสดง destination ปัจจุบัน"กรอบที่สลับหน้า"
NavControllerตัวสั่งย้ายหน้า/ย้อนกลับ + คุม back stack"คนขับ/รีโมท"
  • Destination — ปลายทาง 1 อัน (Fragment / composable / dialog)
  • Action — เส้นทางย้ายจาก destination หนึ่งไปอีกอัน
  • startDestination — หน้าแรกที่แสดงเมื่อเข้า graph
Navigation Graph (nav_graph.xml / NavHost) ├─ HomeFragment (startDestination) │ │ action → detail ├─ DetailFragment └─ ProfileFragment NavController.navigate(action) → เปลี่ยน destination ใน NavHost

3. Back stack (กองประวัติ)

ทุกครั้งที่ navigate() ไปหน้าใหม่ หน้าเดิมจะถูก "วางซ้อน" ใน back stack เมื่อ กด back จะ pop หน้าบนสุดออก กลับไปหน้าก่อน

navigate A → B → C back stack: [A, B, C] (แสดง C) กด back back stack: [A, B] (แสดง B) กด back back stack: [A] (แสดง A)

ควบคุม back stack ด้วย popUpTo

// ไป Home แล้วล้างทุกหน้าจนถึง Home (เช่นหลัง login สำเร็จ)
navController.navigate(R.id.homeFragment) {
    popUpTo(R.id.loginFragment) { inclusive = true }  // เอา login ออกด้วย
    launchSingleTop = true                            // ไม่ซ้อน Home ถ้าอยู่แล้ว
}
  • popUpTo — ย้อน pop ถึง destination ที่ระบุก่อน navigate
  • inclusive = true — pop รวม destination นั้นด้วย
  • launchSingleTop — ไม่สร้างซ้ำถ้าอยู่หน้านั้นอยู่แล้ว (กันกดรัวเปิดซ้อน)

4. ส่งข้อมูลระหว่างหน้า (Safe Args)

Safe Args = Gradle plugin ที่ generate โค้ดให้ส่ง/รับ argument แบบ type-safe (รู้ชนิดตอน compile ไม่ต้องใส่ key เป็น string เอง)

ประกาศ argument ใน graph

<fragment android:id="@+id/detailFragment" ...>
    <argument
        android:name="orderId"
        app:argType="string" />
</fragment>

ส่ง (ต้นทาง) และรับ (ปลายทาง)

// ส่ง — Safe Args generate action ที่รับ orderId ให้เลย
val action = HomeFragmentDirections.actionHomeToDetail(orderId = "1234")
findNavController().navigate(action)

// รับ — ปลายทางใช้ navArgs()
class DetailFragment : Fragment() {
    private val args: DetailFragmentArgs by navArgs()
    // ... args.orderId  (type-safe, เป็น String แน่นอน)
}
อย่าส่ง object ใหญ่/ทั้งก้อนผ่าน args — ส่งแค่ id แล้วให้ปลายทางโหลด ข้อมูลเองจาก repository (กัน state คู่กัน + Bundle ใหญ่เกิน)

5. Single-activity architecture

แนวทางที่นิยม: ใช้ Activity เดียว เป็นโฮสต์ แล้วทำแต่ละหน้าจอเป็น Fragment/composable destination สลับด้วย Navigation Component

  • back stack/การส่งข้อมูลเป็นระบบเดียว จัดการง่าย
  • แชร์ ViewModel ระดับ graph ได้ (navGraphViewModels)
  • transition ระหว่างหน้าลื่นกว่าเปิด Activity ใหม่
ยังต้องมีหลาย Activity เฉพาะกรณี: จุดเข้าจากแอปอื่น/deep link แยก, แยก task, Activity จาก SDK ภายนอก — นอกนั้น single-activity พอ

6. XML Navigation vs Navigation-Compose

ประเด็นXML NavigationNavigation-Compose
นิยาม graphไฟล์ nav_graph.xml (มี editor ลากวาง)เขียนใน Kotlin (NavHost { composable(...) })
destinationFragmentcomposable
ส่งข้อมูลSafe Args (generate)route + arguments (หรือ type-safe API ใหม่)
เหมาะกับโปรเจกต์ View/XMLโปรเจกต์ Compose
เลือกตาม UI ที่ใช้: ถ้าเขียน View/XML → XML Navigation • ถ้าเขียน Compose → Navigation-Compose • ทั้งคู่เป็น Navigation Component ตัวเดียวกันแค่คนละหน้าตา

7. Deep link (เปิดหน้าจากลิงก์/ภายนอก)

Deep link = เปิดแอปไปที่ destination เฉพาะโดยตรง (จาก URL, notification, แอปอื่น)

<!-- ประกาศใน graph -->
<fragment android:id="@+id/detailFragment" ...>
    <deepLink app:uri="myapp://order/{orderId}" />
</fragment>
  • implicit deep link — ระบบ route ให้ตาม uri ที่ประกาศ (เปิดจากภายนอกได้)
  • explicit deep link — สร้าง PendingIntent สำหรับ notification
  • ต้องประกาศ <nav-graph> ใน Manifest เพื่อรับ link จากภายนอก

8. Nested graph + Bottom Navigation

Nested graph = graph ย่อยซ้อนใน graph ใหญ่ — ใช้จัดกลุ่ม flow (เช่น flow ล็อกอิน) หรือให้แต่ละแท็บของ bottom nav มี back stack ของตัวเอง

// ผูก BottomNavigationView กับ NavController — แต่ละแท็บ = destination/graph
binding.bottomNav.setupWithNavController(navController)

// toolbar + ปุ่ม back อัตโนมัติ (top-level = ไม่มี back, ที่เหลือมีลูกศร back)
val appBarConfig = AppBarConfiguration(
    setOf(R.id.homeFragment, R.id.searchFragment, R.id.profileFragment)
)
binding.toolbar.setupWithNavController(navController, appBarConfig)
แต่ละแท็บ bottom nav ควรมี nested graph ของตัวเองเพื่อเก็บ back stack แยก — Navigation Component เวอร์ชันใหม่จัดการ multiple back stack ให้อัตโนมัติ

9. การเลือกใช้

สถานการณ์แนะนำ
โปรเจกต์ View/XMLNavigation Component + nav_graph.xml + Safe Args
โปรเจกต์ ComposeNavigation-Compose (NavHost/composable)
ย้ายหน้าภายในแอปNavController.navigate (ไม่ใช่ startActivity)
เปิดจากลิงก์/notification/แอปอื่นDeep link
bottom nav / แท็บnested graph + setupWithNavController

หลักคิด: ใช้ Navigation Component เสมอสำหรับการนำทางในแอป — อย่ากลับไป จัดการ FragmentTransaction/back stack เองเพราะพลาดง่าย

10. ข้อดี / ข้อเสีย ของ Navigation Component

  • ✅ จัดการ back stack ให้อัตโนมัติ ถูกต้องตามหลัก
  • ✅ Safe Args ส่งข้อมูล type-safe (ลดบั๊ก key พิมพ์ผิด)
  • ✅ graph เห็นภาพรวมการนำทางทั้งแอปในที่เดียว (มี visual editor)
  • ✅ deep link, transition, bottom nav integration ในตัว
  • ✅ รองรับ multiple back stack (แต่ละแท็บแยก)
  • ❌ เรียนรู้ concept เพิ่ม (graph/host/controller) สำหรับมือใหม่
  • ❌ setup Safe Args plugin + dependency
  • ❌ เคสซับซ้อนมาก (nested graph หลายชั้น) config ยุ่งได้
  • ❌ ผูกกับ Jetpack (แต่เป็นมาตรฐานอยู่แล้ว)

11. ภาคปฏิบัติ: สร้างจริง step-by-step (XML)

โจทย์: Home → กดรายการ → Detail (ส่ง orderId) → ปุ่ม back กลับ Home

ขั้น 1 — เพิ่ม dependency + Safe Args plugin

// build.gradle.kts (module :app)
plugins {
    id("androidx.navigation.safeargs.kotlin")
}
dependencies {
    implementation("androidx.navigation:navigation-fragment-ktx:2.8.0")
    implementation("androidx.navigation:navigation-ui-ktx:2.8.0")
}

ขั้น 2 — สร้าง nav graph (res/navigation/nav_graph.xml)

<navigation xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/nav_graph"
    app:startDestination="@id/homeFragment">

    <fragment
        android:id="@+id/homeFragment"
        android:name="com.example.HomeFragment"
        android:label="หน้าแรก">
        <!-- action ไป detail พร้อมส่ง orderId -->
        <action
            android:id="@+id/action_home_to_detail"
            app:destination="@id/detailFragment" />
    </fragment>

    <fragment
        android:id="@+id/detailFragment"
        android:name="com.example.DetailFragment"
        android:label="รายละเอียด">
        <argument android:name="orderId" app:argType="string" />
    </fragment>
</navigation>

ขั้น 3 — วาง NavHost ใน Activity layout

<androidx.fragment.app.FragmentContainerView
    android:id="@+id/nav_host"
    android:name="androidx.navigation.fragment.NavHostFragment"
    app:navGraph="@navigation/nav_graph"
    app:defaultNavHost="true"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />

ขั้น 4 — เชื่อม NavController + toolbar ใน Activity

class MainActivity : AppCompatActivity() {
    override fun onCreate(s: Bundle?) {
        super.onCreate(s)
        val binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        val navController = (supportFragmentManager
            .findFragmentById(R.id.nav_host) as NavHostFragment).navController

        setSupportActionBar(binding.toolbar)
        // Home เป็น top-level (ไม่มีปุ่ม back), หน้าอื่นโชว์ลูกศร back อัตโนมัติ
        val config = AppBarConfiguration(setOf(R.id.homeFragment))
        binding.toolbar.setupWithNavController(navController, config)
    }
}

ขั้น 5 — navigate + รับ argument

// HomeFragment — กดรายการแล้วไป detail
binding.item.setOnClickListener {
    val action = HomeFragmentDirections.actionHomeToDetail(orderId = "1234")
    findNavController().navigate(action)
}

// DetailFragment — รับ orderId แบบ type-safe
class DetailFragment : Fragment() {
    private val args: DetailFragmentArgs by navArgs()
    override fun onViewCreated(v: View, s: Bundle?) {
        val id = args.orderId          // "1234"
        viewModel.load(id)
    }
}
เสร็จแล้ว! ปุ่ม back บน toolbar และปุ่ม back ของระบบทำงานอัตโนมัติจาก Navigation Component — ไม่ต้องเขียน onBackPressed เอง

12. ภาคปฏิบัติ (Navigation-Compose)

// dependency: androidx.navigation:navigation-compose

@Composable
fun AppNavHost(navController: NavHostController = rememberNavController()) {
    NavHost(navController, startDestination = "home") {

        composable("home") {
            HomeScreen(onItemClick = { id ->
                navController.navigate("detail/$id")   // ส่ง id ผ่าน route
            })
        }

        composable(
            route = "detail/{orderId}",
            arguments = listOf(navArgument("orderId") { type = NavType.StringType })
        ) { backStackEntry ->
            val id = backStackEntry.arguments?.getString("orderId")
            DetailScreen(orderId = id)
        }
    }
}

// ย้อนกลับ
navController.popBackStack()

// ล้าง back stack (เช่นหลัง login)
navController.navigate("home") {
    popUpTo("login") { inclusive = true }
    launchSingleTop = true
}
Navigation-Compose เวอร์ชันใหม่มี type-safe navigation (ใช้ @Serializable data class เป็น route แทน string) ลดบั๊กจากการพิมพ์ route ผิด

13. ข้อผิดพลาดที่พบบ่อย

ข้อผิดพลาดผล / วิธีแก้
กดปุ่มรัว → navigate ซ้อนหลายหน้าเพิ่ม launchSingleTop = true หรือเช็ค currentDestination
import navGraphViewModels ผิด packageต้องเป็น androidx.navigation ไม่ใช่ ...fragment
ส่ง object ใหญ่ผ่าน argsBundle ใหญ่/state คู่กัน → ส่งแค่ id แล้วโหลดเอง
ไม่ตั้ง defaultNavHost="true"ปุ่ม back ระบบไม่ทำงานกับ NavHost
observe/navigate ใน Fragment ด้วย this แทน viewLifecycleOwnernavigate ซ้ำ/รั่ว → ใช้ viewLifecycleOwner
ลืม popUpTo หลัง loginกด back กลับไปหน้า login ได้ → ใช้ popUpTo + inclusive
navigate จาก state (ไม่ใช่ event)navigate ซ้ำตอนหมุนจอ → ใช้ one-shot event

14. การทดสอบ

// ทดสอบ navigation ด้วย TestNavHostController
@Test fun `กดรายการแล้วไป detail`() {
    val navController = TestNavHostController(context)
    val scenario = launchFragmentInContainer<HomeFragment>()
    scenario.onFragment { f ->
        navController.setGraph(R.navigation.nav_graph)
        Navigation.setViewNavController(f.requireView(), navController)
    }
    onView(withId(R.id.item)).perform(click())
    assertEquals(R.id.detailFragment, navController.currentDestination?.id)
}
  • TestNavHostController — จำลอง NavController ในเทสต์ เช็ค destination ปัจจุบัน
  • FragmentScenario — launch Fragment แยกในเทสต์
  • Compose → ใช้ createComposeRule + rememberNavController ในเทสต์

15. แนวโน้มในอนาคต

  • Navigation-Compose + type-safe routes เป็นค่าเริ่มต้น — ใช้ @Serializable data class แทน string route (ลดบั๊ก)
  • Predictive back gesture — Android 14+ แสดง preview หน้าก่อนหน้าตอนปัดกลับ → Navigation Component รองรับให้
  • multiple back stack เป็นมาตรฐาน — แต่ละแท็บ bottom nav เก็บ back stack แยก
  • Navigation 3 / adaptive navigation — รองรับจอใหญ่/พับได้ (list-detail layout)
  • สรุป: ทิศทางไป Compose + type-safe + adaptive (หลายขนาดจอ) แต่แนวคิดหลัก (graph/host/controller/back stack) คงเดิม

16. ศัพท์ทางเทคนิค (Glossary)

  • Navigation Component — ไลบรารี Jetpack จัดการการนำทาง
  • Navigation Graph — แผนที่รวม destination + action
  • NavHost / NavHostFragment — ที่แสดง destination ปัจจุบัน
  • NavController — ตัวสั่งย้ายหน้า/คุม back stack
  • Destination — ปลายทาง 1 อัน (Fragment/composable/dialog)
  • Action — เส้นทางย้ายระหว่าง destination
  • startDestination — หน้าแรกของ graph
  • Back stack — กองประวัติหน้าที่เคยเปิด (สำหรับ back)
  • popUpTo / inclusive — ควบคุมการล้าง back stack
  • launchSingleTop — ไม่สร้าง destination ซ้ำถ้าอยู่บนสุดแล้ว
  • Safe Args — plugin generate โค้ดส่ง argument แบบ type-safe
  • Deep link — เปิดหน้าเฉพาะจาก URL/notification/แอปอื่น
  • Nested graph — graph ย่อยซ้อนใน graph ใหญ่
  • NavType-safe route (Compose) — ใช้ data class เป็น route แทน string
